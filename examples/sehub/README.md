# SEHub — a CD2GUI showcase with login management

This example exists to show what **CD2GUI** generates. Almost the entire user
interface is derived from a single class diagram; the only hand-written pages are
the ones CD2GUI deliberately does not cover — login and the application shell.

If you want to change what the application looks like, change
[`models/Sehub.umlp`](models/Sehub.umlp) and rebuild. Do not edit anything under
`frontend/build/cd2gui/` — it is regenerated on every build.

## What is generated

`frontend/build.gradle` sets `withCD2GUI = true`, which runs the `cd2gui` task over
`models/Sehub.umlp` before the normal GUI generator. For each of classes CD2GUI emits five pages:

| Page | Purpose                                                            |
| --- |--------------------------------------------------------------------|
| `<C>Overview` | table of all instances, with delete buttons and a link to the form |
| `<C>Details` | read-only view of one instance plus its association tables         |
| `<C>DetailsEdit` | the editable variant of the same                                   |
| `<C>Form` | create a new instance                                              |
| `<C>Metric` | Different chart types over the class's attributes                  |

On top of that come `CD2GUIDashboard` (the landing page, one row per class) and
`NavigationContainer` (the class tree every generated page is wrapped in).

CD2GUI also emits JSweet hand-written-code classes into `frontend/build/cd2gui/guiImpl/`.
They are wired into the GUI generator's HWC path by the frontend Gradle plugin, so they need no manual copying.

## How the model steers the output

Everything visible in the generated pages is a consequence of the class diagram. The
markers this example uses:

| In `Sehub.umlp` | Effect |
| --- | --- |
| `<<key_attribute>>` | the attribute becomes the first overview column and is exempt from the 8-column cap |
| `<<hidden_in_overview>>` on `User.password` | still editable on the details page, but never rendered into the overview table |
| `/String type` (derived) | rendered read-only as a `GemText`, never as an input |
| `composition [0..1] Directory (containedBy) <-> (contains) Artifact [*]` | see below |

Cardinality decides the widget: a `[1]` or `[0..1]` role becomes a single field, a `[*]`
or `[1..*]` role becomes an association table with add/remove buttons.

### The composite pattern

`Directory` is a subclass of `Artifact` and has a composition *to* `Artifact`. CD2GUI
recognizes that as a Composite pattern and additionally generates a directory tree and a structure graph. 
The details page of a participating class renders itself inside the composite structure.

Making that one association a `composition` is also what turns the overview delete button
into a recursive, composition-aware delete.

## What is hand-written, and why

| Path | Why it is not generated |
| --- | --- |
| `frontend/src/main/gui/gui/login/**` | authentication is outside CD2GUI's scope |
| `frontend/src/main/gui/gui/Start.gui` | the welcome page shown after login |
| `frontend/src/main/gui/gui/PageNotFound.gui` | 404 page |
| `frontend/src/main/gui/gui/Navigation.gui` | the application top bar (logo, user name, sign-out) |
| `frontend/src/main/gui/sehub/SehubNavigation.gui` | GUIVariability adaptation, see below |
| `frontend/src/main/gui/AppGemRouting.ts` | default route plus the `signedInGuard` |
| `frontend/src/main/java/gui/**` | JSweet HWC for the hand-written components above |
| `backend/src/main/java/**` | dummy data, security, and the artifact extractor |

The generated pages have no login check of their own, so `AppGemRouting.ts` attaches a
single `CanActivateFn` to the lazy-loaded `sehub` route. That guards the whole generated
surface in one place.

### GUIVariability - Putting the top bar on generated pages

`Navigation` is included directly by `Start.gui` and `PageNotFound.gui`. The generated pages
cannot be edited, so they get it through **GUIVariability**, a way to customize GUI models generated by CD2GUI, 
see `sehub/SehubNavigation.gui`:

```gui
component SehubNavigation() adapts NavigationContainer {
  before navContainer: sehubNavBar@Navigation();
}
```

Every generated page wraps itself in `@NavigationContainer`, so adapting that one component
puts the top bar on all of them without touching a single generated file. The adapted copy
is written to `build/guiVariability/` and merged over its original into `build/guiModels/`,
which is what the GUI generator then reads.

## Running it

Start the backend with `gradle :examples:sehub:backend:runServer` and the frontend with
`gradle :examples:sehub:frontend:runApp`. The app is then reachable at
`http://localhost:4200`.

Sign in as `admin` / `pwd`, or register a new account. Dummy data is only created when the
user table is empty; the `Project`, `Directory` and `FileArtifact` rows are extracted from
this repository's own source tree by `backend/src/main/java/dummy/`.
